# 『Komame』詳細要件定義書（確定版）

## 1. システム概要・ビジョン

### 1.1 プロダクトビジョン
**「こまめ（Komame）な記録が、確かな安心と資産の芽を育てる」**
現代の家計管理は、現金、クレジットカード（締め日・引き落とし日のズレ）、デビットカード（即時決済）、QRコード決済（事前チャージ／後払い紐付け）、銀行口座振替など、決済手段の多様化により「いつ・どこから・いくら引き落とされるのか」「引き落とし口座の原資は足りているか」を把握することが極めて困難になっています。
『Komame』は、高度な金融知識を持たない一般の消費者が、**直感的なUIで複数決済手段と口座残高・資金移動・引き落とし予定を完全に掌握し、迷わず資金移動できるようにする**とともに、**複数に分散した貯蓄・投資（NISA・定期預金等）の目標進捗を楽しく視覚化する**家庭用家計簿Webアプリケーションです。

## 2. システムアカウント・マルチテナントと権限構造

本システムは、**複数家庭（マルチテナント）の家計簿を1つのアプリケーションで安全かつ高パフォーマンスに管理できるマルチテナント・スキーマ完全分離アーキテクチャ**を採用します。

```mermaid
graph TD
    subgraph Master [プラットフォーム層 (Master)]
        SuperAdmin["最上位管理者 (Super Admin)<br>・システム全体の運用管理"]
    end

    subgraph TenantA [システムアカウント A (山田家専用スキーマ)]
        AdminA["家庭管理者 (Household Admin / 山田太郎)<br>・家族管理・招待<br>・24hリバート実行<br>・CSVフル入出力<br>・家庭内設定・ログ閲覧"]
        UserA["家庭メンバー (Household Member / 山田花子)<br>・明細登録・一括入力<br>・口座/カード確認<br>・ダッシュボード・草生やし"]
        DataA["【山田家専用】スキーマ (tenant_yamada)<br>(口座, 明細, 一時保存, 目標, 監査ログ)"]
        AdminA --> DataA
        UserA --> DataA
    end

    subgraph TenantB [システムアカウント B (佐藤家専用スキーマ)]
        AdminB["家庭管理者 (Household Admin / 佐藤一郎)"]
        UserB["家庭メンバー (Household Member / 佐藤次郎)"]
        DataB["【佐藤家専用】スキーマ (tenant_sato)<br>(口座, 明細, 一時保存, 目標, 監査ログ)"]
        AdminB --> DataB
        UserB --> DataB
    end

    Master -.->|認証・スキーマルーティング| TenantA
    Master -.->|認証・スキーマルーティング| TenantB
```

### 2.1 ロールと利用可能機能

| ロール | 想定ユーザー | 主な利用可能機能 |
| :--- | :--- | :--- |
| **家庭管理者 (Household Admin)** | 家計の主管理者 (世帯主等) | 家族ユーザーの招待・管理、パスワード要件設定、24時間チェックポイントリバート実行、家庭内全操作ログ閲覧・特定条件エクスポート、CSVフルインポート・エクスポート、全家計簿機能 |
| **家庭メンバー (Household Member)** | 家族・パートナー | 1件/店舗一括/費目一括明細登録、一時保存（手動/自動）、ダッシュボード閲覧、口座残高・カード引き落とし予定確認、貯蓄目標進捗・草生やし、個別CSVエクスポート |
| **最上位管理者 (Super Admin)** | システム運営者 | システム全体の稼働監視、世帯アカウントの発行/停止 |

### 2.2 複数家庭所属への拡張性（先行N:M互換設計）
- 初期リリース時は **「1ユーザー = 1つの家庭アカウントに所属」** としてシンプルに運用。
- 内部データ構造は `users` - `household_memberships` - `households` の多対多構造で構築されており、**将来「1人のユーザーが実家の家計簿と自宅の家計簿を画面上で切り替えて管理する」機能へ移行する際も、DBの再構築やデータ移行は一切不要（0秒移行）**。

## 3. 初期機能要件（詳細仕様）

### 【要件 1】認証・セキュリティ・世帯サインアップ
- **1-1. ログイン/ログアウト**: メールアドレス（将来の外部通知用）とパスワードによる認証。
- **1-2. セルフサインアップ & 家族招待フロー**:
  - 初回ユーザーはサインアップ時に「世帯名（例: 山田家）」を入力して新規登録（自動的にその家庭の管理者 `Household Admin` に就任）。
  - 家族の追加は、管理者が管理画面から「家族招待リンク発行」または「メールアドレス登録による招待」を行い、家族が参加。
- **1-3. パスワード要件管理**:
  - 管理者画面にて「最小文字数」「英大文字・小文字・数字・特殊文字の必須有無」等を動的に設定可能。
  - 新ポリシーは「新規登録時」および「次回パスワード変更時」に適用。
  - パスワードハッシュ化は `Argon2id` を採用。
- **1-4. セッション管理**: Secure / HttpOnly Cookie + JWT によるセキュアな世帯コンテキストセッション。

### 【要件 2 & 5】明細登録・資金移動・サジェスト
- **2-1. 1件ずつの明細登録**: 日付、支払元、費目（ID紐付け）、金額、店舗/取引先、タグ、簡易メモ（個数やレシート差異）、色分け貯蓄指定。
- **2-2. 同じ店舗に対する一括登録画面**: 1つの店舗レシートの複数品目を表形式で行追加・一括登録。
- **2-3. 同じ費目に対する一括登録画面**: 1つの費目（食費等）について複数店舗・日付を連続登録。
- **2-4. タグ付け & カラーラベリング**: 支出や資金移動に色付きタグ（`#固定費`, `#自己投資`等）を付与。
- **2-5. 離脱時ガード（未保存警告）**: フォームに入力途中の値がある状態で画面遷移やタブ閉じを試みた場合、確認ダイアログを表示（未入力時は即時遷移）。
- **2-6. 簡易メモ機能**: レシート表記と実際の商品名の相違や、野菜の個数（「玉ねぎ 3個入」）などを記録。
- **5. 機械的サジェスト機能**: 店舗名入力時に過去履歴から店舗名を補完し、決定時に最も使われた「費目」「支払元」を自動提案（1タップ適用）。

### 【要件 6】2段階の一時保存機能（明示的 & 自動保存）
- **6-1. 明示的一時保存 (Manual Draft)**: 「一時保存」ボタン押下で保存（1件保持、既存がある場合は上書き警告）。
- **6-2. 自動一時保存 (Auto Draft)**: **「キー入力停止後2秒（デバウンス）」** で自動退避。画面右下に控えめなトースト（「自動保存しました」）を表示。
- **6-3. 再開メニュー**: 各登録メニューのトップに手動・自動の保存日時・入力件数を比較表示し、ワンタップで再開可能。
- **6-4. 警告表示**: 自動保存データがある状態での新規入力時、および手動保存データがある状態での手動保存時に警告を表示。

### 【要件 8, 9, 10, 11, 12, 18】口座・決済手段・資金フロー・色分け管理
- **8 & 10. 口座・カード・決済手段の登録**:
  - 銀行口座（普通・定期）、プリペイドウォレット（PayPay、Suica等）、クレジットカード、デビットカード、現金を登録。
  - **クレジットカード支払いの扱い（確定仕様）**: クレジットカード登録時に「締め日（1〜28日 / 月末）」と「引き落とし日（1〜28日 / 月末）」および「引き落とし月（1:翌月 / 2:翌々月）」を設定し、一括払いの期日を自動算出。分割・リボ・ボーナス払いは将来拡張とする。
- **11. 残高管理 & 会計連動ロジック**:
  - デビットカード/現金/QR残高払い: 登録と同時に該当口座・ウォレット残高が即時減少。
  - クレジットカード払い: 登録時点では銀行口座残高は減少しない（次回引き落とし予定負債として計上）。引き落とし確定時に銀行口座残高が減少。
- **9. クレジットカード引き落とし予定額・原資チェック**:
  - 締め日・引き落とし日ロジックに基づき次回引き落とし予定額を集計し、紐づく銀行口座の現在残高と比較して「原資充足」または「不足（あと〇〇円不足）」を警告。
- **12. 資金フローの可視化**: 口座引き落とし、窓口引き出し、カード決済、チャージ、投資振替を「どこからいくら出ていくか」一元追跡。
- **18. 口座内での疑似的な資金色分け（バーチャル貯蓄・取り分け）**:
  - 口座内の残高の一部を特定用途（車検用・非常時等）として色分けロック。
  - ダッシュボードでは「総資産」と「実質利用可能残高」の2軸で表示。
  - 不足時は「色分け貯蓄の解除」または「他行からの資金移動」を具体的にサジェスト。

### 【要件 4】費目管理（マスターID管理 & 初期プリセット）
- 費目は内部IDで管理。階層構造（大分類/中分類）に対応。
- 費目名やアイコン・カラーを変更しても、過去のすべての登録明細の費目名が再登録不要で即座に連動更新。
- 新規家庭アカウント作成時に日本の標準家計簿プリセットを自動シード投入。

### 【要件 7】データインポート・エクスポート (CSV)
- **文字コード**: 日本のExcelで文字化けしない **UTF-8 (BOM付き)** を標準採用。
- **インポート**: 家計簿明細CSVの取り込み（マッピング設定、同一日・店舗・金額の重複候補警告）。
- **権限**: フルエクスポートおよびCSVインポートは **「家庭管理者 (Household Admin)」のみ実行可能**。個別エクスポートはメンバーも可。

### 【要件 14, 15, 17, 17-2】ダッシュボード・統計・目標・検索
- **14. ダッシュボード**: 月間収支、決済手段別比率、費目別円グラフ、直近の引き落としアラート。
- **15. 単純検索**: 費目、日付範囲、キーワード、店舗名、決済手段、タグによる高速絞り込み。
- **17. 収入登録**: 額面給与、税金・社保控除、手取り所得、臨時収入の入力。
- **17-2. 貯蓄目標管理**: 複数貯蓄先（普通預金、定期、NISA等）を合算/単独で目標額に対する達成率（%）と推移グラフを可視化。

### 【要件 16】継続モチベーション・ゲーミフィケーション
- **こまめ草生やし（Activity Bean Heatmap）**: 家計簿を記録した日に緑色の豆アイコンがカレンダーに点灯し、継続ストリーク（日数）を表示。
- **まめの樹（Bean Sprout）育成**: 記録や目標達成に応じて、画面上の「こまめちゃん」の新芽が成長するインタラクション。
- **やさしいほめ言葉**: 予算内達成時や節約できた時に前向きなメッセージを通知。

### 【要件 3, 21, 22】管理者機能・操作ログ・24時間チェックポイントリバート
- **3-1 & 21. 操作ログ**: いつ・誰が・どの画面で何のデータを登録/更新/削除したかを簡潔に記録。
- **3-2. ユーザー管理**: 家族メンバーの招待、権限変更、パスワードリセット、無効化。
- **3-3. 条件付きログエクスポート**: ユーザー・期間・操作種別を指定してCSV/JSON出力。
- **3-4. システム設定**: 通貨表示（¥ / $ / €）、日付フォーマット、パスワード強度ポリシー。
- **22. 24時間チェックポイントリバート**:
  - トランザクションごとにチェックポイントを作成（有効期限24時間）。
  - 指定時点以降の明細データおよび連動した口座残高を該当状態に完全ロールバック。
  - **一時保存データのリセット**: リバート実行時、対象ユーザーの一時保存データ（手動/自動）は削除され、**空の状態に初期化**。
  - **家族影響警告**: 同一家庭内の他メンバーが登録した明細も巻き戻される旨の影響サマリーを一覧表示し、二重確認（確認キーワード入力）を必須化。

### 【要件 13, 19, 20, 23】UI/UX・テーマ・通知
- **13. レスポンシブ**: スマホ（iPhone）最優先。スクロール連動ヘッダー開閉、片手操作ボトムナビ、テンキー自動起動。
- **19. 項目ヘルプ**: 各入力項目の「？」アイコンでポップアップ解説。
- **20. テーマ切替**: 5種類の洗練されたカラーテーマ（①Natural Komame [デフォルト], ②Warm Latte & Washi, ③Modern FinTech Indigo, ④Forest & Mint Clean, ⑤Slate Minimal Dark）を即時切替。
- **23. アプリ内通知ボックス**: 引き落としアラート、資金不足サジェスト、目標マイルストーンを表示。

## 4. データ削除ポリシー（確定仕様）

| 対象データ | 削除方式 | 具体的挙動 |
| :--- | :---: | :--- |
| **費目マスター (`categories`)** | **論理削除 (アーカイブ)** | `is_archived = true` となり新規選択肢から非表示。過去の明細やグラフの表示は完全維持。 |
| **口座・決済手段 (`accounts`, `payment_methods`)** | **論理削除 (非活性化)** | `is_active = false` となり新規選択肢から非表示。過去の決済履歴・引き落としデータは維持。 |
| **家族ユーザー (`household_memberships`)** | **論理削除 (無効化)** | ステータスを `inactive` にしてログイン遮断。過去の登録履歴は記録保持。 |
| **支出・収入明細 (`transactions`)** | **論理削除 / ログ退避** | 画面・残高から即時除外。`audit_logs` に退避され、24hリバート時はログから完全復元。 |
| **一時保存データ (`drafts`)** | **物理削除** | 一時作業データのため、破棄・上書き・リバート時はDBから物理削除。 |
| **家庭アカウント全体の退会** | **物理完全抹消** | 個人情報保護のため、該当世帯スキーマ（`DROP SCHEMA tenant_xxx CASCADE`）を物理完全抹消。 |

## 5. 将来拡張要件

1. **レシートOCR自動入力**: 写真から品目・店舗・金額を抽出し一括登録画面へ自動入力。
2. **自然言語検索**: 自然言語による購入履歴の検索。
3. **AI費目サジェスト (LLM)**: 外部API（Gemini等）またはローカルLLM（Ollama）による推論。
4. **外部公開REST API**: 将来のモバイルネイティブアプリ（iOS/Android）連携用APIエンドポイント。
5. **モダン認証**: OAuth 2.0 (Google/Apple), Passkeys (WebAuthn)。
6. **システム外通知**: カード引き落とし前のメール通知（SendGrid / Resend等）、LINE通知。
7. **未来日支出予定**: 年月での仮登録 → 支払日確定時に日指定。
8. **PDFレポート出力**: 統計グラフ・月次収支報告書のPDF生成。
9. **大画面向け高度統計・インタラクティブグラフ表示（レスポンシブ「lg」サイズ以上限定）**:
   - 年間・月間推移、店舗ごと、費目ごと、収入情報などの多角的な家計統計情報。
   - 円グラフ、棒グラフ、折れ線グラフ、積層グラフなどの表示形式をユーザーが自在に選択・切り替えて可視化・分析できる機能。
